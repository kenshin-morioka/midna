# 背景

v0.1（[設計](midna_design_doc_v0_1.md)）で `midna chat` によるローカル LLM との対話はできた。ただ、本来やりたいのは Claude Code のようなコーディングエージェントであり、対話だけでは「ファイルを読んで、直して、確認する」という作業を任せられない。その第一歩として v0.2 を立ち上げる。

# 目的

- Midna がファイル操作とコマンド実行を通じて、手元のプロジェクトに対する作業をこなせるようにする
- 危ない操作（書き込み・コマンド実行）は実行前にユーザーが止められるようにする
- `midna` と打つだけでエージェントが立ち上がるようにする

# スコープ

## ゴール

- `midna`（引数なし）でエージェントモードが起動する。`midna chat` はツールなしの対話として残す
- 組み込みツール 4 つ: `read_file` / `write_file` / `list_dir` / `run_shell`
- Ollama の tool calling でツール実行の要求を受け取り、結果を返して会話を続ける（[ADR 0004](../adr/0004-ollama-tool-calling.md)）
- 危険度に応じた権限確認（[ADR 0005](../adr/0005-risk-based-permissions.md)）

## ノンゴール

- ファイルの部分編集ツール（diff / patch 適用）— まずは全文上書きで始める
- 許可の記憶（「今後も許可」）や設定ファイルによるポリシー変更
- ストリーミング応答、Ctrl+C のシグナル処理
- 作業ディレクトリ外へのアクセス制限（パスのサンドボックス化）
- chat / agent 以外のモード、Ollama 以外の provider
- agents / skills / commands / メモリ永続化

## エンドポイント以外の設計

- エージェントループ（1 ユーザー入力あたりの流れ）
  ```mermaid
  flowchart TD
      Input[ユーザー入力] --> Ask[LLM に問い合わせ<br>会話履歴 + ツール定義]
      Ask --> HasCalls{tool_calls あり?}
      HasCalls -- なし --> Show[応答を表示して終了]
      HasCalls -- あり --> Perm{権限判定}
      Perm -- Allow --> Exec[ツール実行]
      Perm -- Ask --> Confirm{y/N 確認}
      Confirm -- y --> Exec
      Confirm -- N --> Denied[拒否した旨を結果にする]
      Exec --> Push[結果を role: tool で履歴に追加]
      Denied --> Push
      Push --> Ask
  ```
- `Tool` trait: 名前・説明・引数の JSON Schema・危険度（`Risk`）・実行本体を持つ。`ToolRegistry` が一覧と名前引きを提供
- ツールの失敗と実行拒否はエラーで落とさず、結果文字列として LLM に返す（LLM が続きを判断できるようにする）
- 往復は 1 入力あたり 16 step まで。超えたらエラーにして無限ループを防ぐ
- 途中でエラーになったターンは履歴ごと巻き戻す（壊れた文脈を次ターンに引き継がない）
- `read_file` は 64KB、`run_shell` の出力は 32KB で打ち切り（LLM のコンテキスト溢れ対策）。`run_shell` は 60 秒でタイムアウト
- `Provider::chat` はツール定義（`ToolSpec`）も受け取る形に変更。ツールなしの呼び出しは空スライスを渡す
- CLI: `--model` / `--host` / `--verbose` はサブコマンド共通のグローバル引数にする

# 懸念点

- パスの制限がないため、許可すれば作業ディレクトリ外も読み書きできる。個人の手元利用を前提とした割り切り。サンドボックス化は後続で検討する
- 書き込みが全文上書きのみなので、大きなファイルの部分修正は LLM が全文を再生成することになり非効率。部分編集ツールは後続で足す
- 小さいモデルはツールの引数を間違えたり、不要なツール呼び出しをすることがある。失敗を結果として返す設計でループ内の自己修正に期待するが、限界はある
- 毎回 y/N を聞く運用は作業が長くなると煩わしい。許可の記憶はポリシー設定の仕組みと合わせて後続で設計する
